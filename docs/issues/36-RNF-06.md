# RNF-06 · Mantenibilidad y calidad del código
<!-- etiquetas: requerimiento no funcional, historia de usuario, estado: hecho -->

## Historia de usuario

**Como** desarrollador del proyecto, **quiero** un código organizado, documentado y con pruebas automáticas, **para** cambiarlo sin romper lo que funciona.

## Descripción

Cuatro repositorios: el frontend (HTML, CSS y JavaScript con módulos, sin frameworks), el backend y el servicio de IA en Spring Boot por capas (controlador, servicio, repositorio) organizados por módulo, y la base de datos (DBPatSft), cuyas migraciones Flyway GitHub Actions prueba en una base vacía y aplica a Neon. Catálogo de patrones de diseño (docs/DesignPatterns.md del backend). Pruebas automáticas: backend (111) y servicio de IA (119) con JUnit y H2, frontend (56) con node:test y el firmware del medidor con pruebas en el computador; GitHub Actions las ejecuta en cada cambio.

## Criterios de aceptación

- [x] Las pruebas automáticas pasan antes de publicar.
- [x] Cada patrón de diseño documentado indica su función y su prueba.
- [x] El README explica cómo instalar, configurar y desplegar.
